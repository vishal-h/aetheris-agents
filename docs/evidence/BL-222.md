# BL-222 — a skill row can be INSERTED already approved, bypassing the gate
Moved from docs/backlog-2026-06.md at fd53474, 2026-09-14. Body verbatim; corrections and later evidence append below.
---
**Status:** OPEN
**Kind:** defect · **Contract:** D7
**Size:** S · **Priority:** medium
**Section:** harness (`../aetheris/lib/aetheris/store.ex`)

m14 T11 made the approval transition one-way and unrepeatable: `approve_skill/3` writes only a
`validated` row, and `set_skill_status/2` can neither reach nor leave `approved`. That covers
transitions. It does not cover creation.

`insert_skill/1` accepts any status in `Skill.statuses/0`, so a row can be inserted already
`approved`, with any `approved_by` and `approved_at`, never having passed `Skill.Gate`.
`test/aetheris/skill/store_test.exs`'s parametrised `insert/get round-trips status` case does exactly
this today.

**Why it matters.** m14 T12 serves entries on the strength of `status == "approved"`. An approved row
that no gate produced is indistinguishable at the serving path from one that two controls validated
and a human approved.

**To decide as part of the row.** Whether insert refuses the lifecycle states outright, or whether
the invariant belongs somewhere a test fixture can still reach. The round-trip test is a legitimate
consumer of the current behaviour; its replacement is part of the work.

**Done when.** No write path other than `approve_skill/3` can produce a row with `status:
"approved"`, and a test asserts that `insert_skill/1` cannot.

`Source: m14 T11, harness `737a8b4` (pushed), surfaced 2026-09-13. Citations resolved at that
commit: `insert_skill/1` is `lib/aetheris/store.ex:132`, whose only guard is
`Skill.valid_status?/1` at `:1323` (`lib/aetheris/skill.ex:78`, set `:28`); `set_skill_status/2` is
`store.ex:257` and `approve_skill/3` is `:277`; the parametrised case is `store_test.exs:139`–`:163`.
T11's notes name the gap at `docs/aetheris/milestones/m14-t11-implementation-notes.md:51`–`:55`.`

`approve_skill/3` became `approve_skill/4` at BL-223 (harness `017f4e2`); this row's text predates that. (Recorded at the BL-223 review, 2026-09-13.)
