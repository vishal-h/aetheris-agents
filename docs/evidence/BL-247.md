# BL-247 — the gate's result does not record which control-2 check rejected a candidate
Moved from docs/backlog-2026-06.md at fd53474, 2026-09-14. Body verbatim; corrections and later evidence append below.

---
**Status:** OPEN
**Kind:** defect · **Contract:** D8
**Size:** S · **Priority:** medium
**Section:** harness (`../aetheris/lib/aetheris/skill/frequency_prior.ex`, `../aetheris/lib/aetheris/skill/gate.ex`)

Control 2 now rejects for two independent reasons: the candidate's sequence is a dominant-set member,
or it is a contiguous subsequence of the modal whole-run path. The result carries `:re_encodes` and
nothing more, so a reader must recompute the reason from `dominant` and `modal_path`.

BL-213 covers where verdict reasons live durably; this is a different gap — the reason is not computed
at all, so there is nothing for BL-213 to store.

**Done when.** The control-2 result names which check fired, both when only one does and when both do;
a test asserts a candidate matching only the modal path reports that reason and not membership.

`Source: the corpus-build review, 2026-09-14; harness `19ba133` (pushed). Citations resolved at that
commit: `re_encodes?/2` returns a bare boolean from a `cond` whose first true arm wins, membership at
`lib/aetheris/skill/frequency_prior.ex:199` and the modal path at `:200`, so when both hold only
membership is even evaluated; `assess_control_2/2` maps `true` to `:re_encodes` at
`lib/aetheris/skill/gate.ex:337`–`:338`; the `control_2` type is `outcome`, `insufficiency`,
`candidate_sequence` and `prior` at `:143`–`:148`, and `decide/2` turns it into the single reason
`:control_2_re_encodes` at `:524`.`
