# BL-255 — the kernel-ceiling decrease-only rule sets zero headroom, so the next backlog filing fails --strict

**The defect.** BL-201 wrote the manifest header's **Kernel ceiling** rule, which says *"a round that
shrinks the kernel lowers it to the new measured size"*. A ceiling at the exact size leaves no room for
`docs/backlog-2026-06.md`, which is itself a kernel row, to grow, and every filed row grows it.
`kernel_budget`'s over-ceiling WARN is not strict-exempt, so the first backlog filing after such a
ratchet turns `drift_check --strict` red, and no filed row explains why.

**Not live at `ab57831`.** The ceiling is 250,000 bytes and the kernel 241,691
(`python3 scripts/drift_check.py --check kernel_budget`), leaving 8,309 bytes of headroom. No round
that reduces the kernel is filed.

**Candidate fixes.** Ratchet to the measured size plus a stated slack, or round up to a stated
boundary. Either way, the rule also says what re-tightens the slack as the kernel shrinks toward the
122,880-byte target.

`Source: filed 2026-09-15 by claude-code at agents ab57831, from the flagged observation in BL-201's
review packet (bl-201-packet.md, session scratchpad): "the next commit that files a row goes over it,
and because this WARN is not strict-exempt". The arbiter ruled the defect is in the rule, not in the
BL-201 work.`
