# BL-262 — cap composition: per-schedule runtime and TTL values must be tighten-only

**The finding.** No per-schedule runtime or TTL value exists yet, and no derived default that one could only shorten: `RunConfig.from_map` takes a template's values as given (`lib/aetheris/run_config.ex:177`, `max_steps: Map.get(map, "max_steps", 10)`). The moadim brief's rule — per-routine values *"can only shorten, never extend"* the derived defaults, its third sighting of the QM tighten-only lattice — has nothing to govern until BL-257 and BL-261 introduce caps, so this row is the obligation those rows inherit.
