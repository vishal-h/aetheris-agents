# BL-265 — a default or inherited `max_duration` bound for unattended scheduled runs

**The finding.** BL-262 made `:max_run_duration` a maximum on an **explicit**
`max_duration` only. It defaults to `nil`, and a run that sets no `max_duration`
stays unbounded, both on first start and on resume (`RunConfig.from_map/3`,
harness `b079130`). A scheduled run whose template sets no limit therefore still
has no time limit. The moadim brief's tighten-only rule (*"can only shorten, never
extend"* the derived defaults, `docs/aetheris/research/moadim-hardening-catalog-2026-08.md:86-88`)
assumes a derived default exists. None does.

**Why it was deferred, not built.** At BL-262's plan stop the arbiter rejected
"absent inherits the ceiling". Two things must be settled before any default
lands:
- **Long-lived runs.** Is there a legitimate run that lives longer than the
  intended default? m13 persistent agents are the obvious candidate.
- **Resume.** BL-261a's watchdog measures from the run's *original* start
  (`Agent.Server.arm_max_duration_watchdog/2`). A default applied on resume would
  therefore stop, at once, a parked run that was admitted unbounded and has
  already outlived it. So the ruling has to say how resume grandfathers runs that
  were previously unbounded.
