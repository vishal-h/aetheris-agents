# BL-268 — terminal transitions are not final: events and status writes follow the first terminal write

**The finding.** Harness at `191970a`:
1. **The loop outlives cancel and watchdog.** It runs in a `Task.start_link` the server never stops (`lib/aetheris/agent/server.ex:273-274`), and `lib/aetheris/execution/loop.ex` has no run-status check (`grep -nE "status|cancel"` matches only child-status lines and the `git_status` tool name).
2. **Worker `:DOWN` appends after terminal.** `error{worker_crashed}` is appended with no status guard (`server.ex:564-580`). Scout DB census of `priv/aetheris.db`: 4 `done` runs end `run_complete` → `error`; 18 `worker_crashed` events, 9 of them in `done` runs. Why the worker exits after completion is not established.
3. **Watchdog then `run_failed` writes `failed` twice.** `server.ex:911-916`, then `server.ex:536`; the `run_failed` clause guards only `:cancelled` (`:527`).
4. **A second `run_complete`.** `drive-example-kOs3_Q` has `run_complete` at seq 10, then `prompt_built`, `llm_called`, `llm_responded`, `run_complete` at seq 14, status `done` (same census). Cause not established.
5. **A restarted `Agent.Supervisor` does not resume.** It is `:permanent` under `RunSupervisor` (`lib/aetheris/admission.ex:472`); its `Agent.Server` re-inits `status: :idle` (`server.ex:240`) and nothing calls `:run`. Inferred, not exercised — confirm.
6. **A status-less upsert regresses a terminal run.** `do_upsert_run` binds `Map.get(attrs, :status, "running")` (`lib/aetheris/store.ex:1406`), and its update arm sets `status = excluded.status` unconditionally (`:1398`), so `Store.upsert_run(id, %{})` on a terminal run writes `running` back. BL-266 T0 defends the stream: a row carrying `terminal_seq` under a non-terminal status drains through `terminal_seq` and closes with `inconsistent_run_state` (BL-266 brief §3 C5.8). Correcting the write behaviour is this row's. Added 2026-09-18 during BL-266 T0 apply, exercised by that round's T25b.

**Not blocking BL-266.** BL-266's `runs.terminal_seq` excludes every post-terminal append from the stream (`docs/aetheris/backlog/bl-266-run-event-streaming.md` §3 C5).
