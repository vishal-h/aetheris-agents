# BL-270 — a busy read crashes the singleton Store: `collect_rows/3` has no `:busy` arm

**The finding.** `collect_rows/3` matches `{:row, _}`, `:done` and `{:error, _}` from `Exqlite.Sqlite3.step/2` (`lib/aetheris/store.ex:2258-2264`), but `step/2` can also return the bare atom `:busy` (`deps/exqlite/lib/exqlite/sqlite3.ex:261`, exqlite 0.36.0). A read that hits `SQLITE_BUSY` after `busy_timeout` expires (`:701`) raises `CaseClauseError` inside `Aetheris.Store`. That crashes the singleton Store, so every concurrent run's Store call exits, append path included. The write path already has this arm: `run_stmt/3` returns `{:error, :busy}` (`:2244`), added at BL-007 t4 for the same reason.

**Aggravated by.** BL-266 T0 adds read volume on this path: `Store.events_after/3` and `run_stream_state/1` run on every stream open and wakeup (`docs/aetheris/backlog/bl-266-run-event-streaming.md` §3 C15). T0's subscriber tolerates Store exits (C7), so it survives the crash, but the crash itself is outside T0 (ruling R-R5).
