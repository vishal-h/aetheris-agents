# BL-272 — Rig infers run completion from `run_complete` on the poll path

**The finding.** `useRunEvents` stops polling when any event has `event_type === 'run_complete'` (`rig/src/hooks/useHarness.ts:121-125`), and `RunList` EventsContent displays `done` from the same test (`rig/src/components/modules/harness/RunList.tsx:470-471`). BL-266 C5.7 says terminal state is never inferred from event type, and the brief's F6 records `done` runs whose last event is `error`, after `run_complete`. Done when both sites take completion from the run row's status (`TERMINAL_STATUSES`, `useHarness.ts:141`), or from a stream control frame where one is present, and neither reads `run_complete` as a status.

**Scope.** BL-266 T3 left both sites alone (its ruling 11) and switched only `TrajectoryView`'s reconstructed path to the stream.
