# BL-277 — `compile.aetheris_worker` copies the worker and exec-server binaries unconditionally, so any mix invocation fails while either is running

**The finding.** `Mix.Tasks.Compile.AetherisWorker.run/1` copies both Rust binaries into `priv/`
on every compile, with no staleness check. `copy_binary/3` at
`lib/mix/tasks/compile/aetheris_worker.ex:46` is a bare `File.copy!/3`, and `run/1` calls it
unconditionally at two sites:

| Site | Binary | Destination |
|---|---|---|
| `aetheris_worker.ex:32` | `aetheris_worker` | `priv/worker/aetheris_worker` |
| `aetheris_worker.ex:33` | `aetheris_exec_server` | `priv/exec_server/aetheris_exec_server` |

**The defect is the unconditional copy in `run/1`, not the worker binary specifically: freeing
one binary relocates the failure to the other site rather than clearing it.** A running binary
cannot be overwritten, so while either is up every `mix` invocation in the harness aborts during
compilation:

```
** (File.CopyError) could not copy from "native/target/release/aetheris_worker"
   to "priv/worker/aetheris_worker": text file or pseudo-device busy
    (aetheris 0.1.0) lib/mix/tasks/compile/aetheris_worker.ex:46: copy_binary/3
    (aetheris 0.1.0) lib/mix/tasks/compile/aetheris_worker.ex:32: run/1
```

**Why a running worker holds the file the compiler writes.**
`_build/dev/lib/aetheris/priv` is a symlink to `../../../../priv`, so the binary Mix executes and
the binary Mix copies to are one inode:

```
/home/it/sandbox/elixirws/aetheris/_build/dev/lib/aetheris/priv -> ../../../../priv
/proc/2508370/exe -> /home/it/sandbox/elixirws/aetheris/priv/worker/aetheris_worker
/proc/2508371/exe -> /home/it/sandbox/elixirws/aetheris/priv/exec_server/aetheris_exec_server
```

**Blast radius.** Every gate, not only agent runs: `mix test`,
`mix compile --warnings-as-errors` and `mix aetheris server` alike. A live harness is the normal
state during any click-through, so the gates are unrunnable exactly when a ticket most needs them.
Observed at BL-276, which could not run scout step 4 or any harness gate until the operator
stopped a 3h54m IEx session.

**No escape, and two non-workarounds.** There is no `--no-compile` or skip flag for this compiler
(`aetheris-agents/CLAUDE.md` §Learning — rig-p9, which records the same `ETXTBSY` from the nested
`mix aetheris run` direction). `MIX_ENV=test` does not help: `_build/test/lib/aetheris/priv` is a
symlink to the same `priv/`, so the copy target is unchanged. A scratch worktree would compile,
but it is a different tree with a different store, and verifying a recipe against it rather than
against the operator's environment is the failure recorded at
`aetheris-agents/CLAUDE.md` §Learning — BL-007 (t4 r3–r6): the simulation verifies the simulation.

**Diagnosed, not fixed.** Nothing in this row was changed.

**Deviation.** The cc:prompt dictated this row's title and done-when naming the worker binary
alone. Both were corrected to name the worker and the exec server, verified separately, so a
fixing round cannot satisfy the done-when by guarding `:32` and leaving `:33` reachable. The
correction is to the prompt's wording, not to the filing.
