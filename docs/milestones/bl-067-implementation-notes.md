## Built stronger than the row proposed, and why

The backlog row's Fix was "a generator emits the derived block to a file; the assembler pastes
it verbatim". That still ends with an LLM transcribing a counted block into `write_file` — the
same actor the ticket exists to remove, and the m2a rule says it will improvise instead of
round-tripping the blob. Concatenation does not need a model either. So
`scripts/assemble_matrix.py` performs the whole assemble and
`agents/capability_matrix_assemble.exs` is deleted. The row's Fix/Done-when were rewritten in
the same commit so the next reader does not re-adjudicate the difference.

## Design decisions

**`SECTIONS` is an explicit ordered constant, not directory order.** The matrix's section order
is an editorial decision; `glob` order would silently reorder the document when a file is added.
The cost is that a section file with no `SECTIONS` entry is skipped — so the script names it on
stderr (`section file not in SECTIONS, ignored: …`) rather than dropping it silently.

**Tools cells: backticked tokens, with a prose fallback.** Every Tools cell is parsed for
`` `tool` `` tokens. A non-empty cell with *no* backticks is taken whole as one entry — that is
how `MCP servers (corpus_search, lattice)` (provenance's `search_agent.exs`) survives; dropping
it would understate the tool surface, and it is a real capability, not decoration.

**Identical tool sets group by set equality, not cell order.** The report's own heading says
*sets*. Cell order is a section-agent choice and would otherwise split a genuine group in two.
Display order within a group is the first-seen agent's cell order; groups are ordered largest
first, ties by first appearance.

**Agent identity is the file stem plus use case.** The retired agent printed `cot1 (api/tenant —
TAP Protocol — Tenant side)` for a row whose *file* is `at1cmd.exs` — the label read as the file
name. Now: `payslip_orchestrator (payslip)`, and where one file contributes several rows to a
section (an OrbConfig with several RunConfigs) the label disambiguates:
`at1cmd:cot1 — TAP Gateway (api/tenant)`.

**Script-name overlaps are not restricted to `.py`.** The retired prompt said ".py filename";
provenance's Scripts table legitimately lists `register_eval_task.exs`. A script row is a script
row.

**Degrade, don't crash.** Missing section → `_Section not available._`, a 0/0 Summary row, a
stderr WARN and exit 1 (the sprint then reports the matrix as partial). Missing or malformed
tables → 0 rows + WARN. No uncaught exception can break the stdout contract.

**No timestamp in the header.** `_Generated by …_` is static, so two runs over unchanged
sections are byte-identical and a matrix diff only ever shows a real change. (Rig's
`capability_matrix_load` keys off this line, `## ` headings, and the two tables —
`rig/src-tauri/src/commands/capability_matrix.rs:44-60` — so the document shape is unchanged.)

## The curated-restore stopgap, and its one real leak

`docs/.sections/` is gitignored, so the sprint's eight section agents rewrite every section
(BL-068). The sprint case was run in full for evidence and **its matrix was discarded**; the
committed matrix was assembled over the curated sections restored from
`HEAD:docs/capability-matrix.md`.

To show the two are the same artifact where BL-067 is concerned, the assembler was run over both
section sets and the derived blocks compared. Result: **per-section counts, totals, all four
tool-set groups (with identical agent lists), and script overlaps are identical**; the regen's
own run reported the same `26 agents, 67 scripts`. One entry differs — the section agent reworded
the prose Tools cell, `MCP servers (corpus_search, lattice)` → `(MCP: corpus_search, lattice)` —
which changes one entry of the unique-tools line.

That is worth stating plainly rather than rounding off: the derived block is curation-invariant
for everything counted from *structure* (rows, backticked tools, names), but a prose Tools cell is
simultaneously curation and data, so it is regen-fragile. It is a second instance of what BL-068
owns, now with a concrete example.
